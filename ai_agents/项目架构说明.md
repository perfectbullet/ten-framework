## 1. tenapp 子项目

### 1.1 项目定位

**tenapp** 是一个标准的 **TEN App**（TEN 应用），位于 `ai_agents/agents/examples/voice-assistant/tenapp/` 目录。它是一个完整的语音助手示例应用。

### 1.2 核心功能

实现端到端的语音对话系统，包含以下组件：

| 组件 | 功能 | 使用的扩展 |
|------|------|-----------|
| **ASR** | 语音识别，将用户语音转为文本 | `aliyun_asr_bigmodel_local_python` |
| **LLM** | 大语言模型，生成对话回复 | `openai_llm2_python` (DeepSeek) |
| **TTS** | 语音合成，将文本转为语音 | `cosy_tts_python_local` |
| **VAD** | 语音活动检测，检测说话开始/结束 | `silero_vad_python` |
| **RTC** | 实时音视频通话 | `agora_rtc` |

### 1.3 架构特点

```
用户语音 → Agora RTC → VAD → ASR → LLM → TTS → Agora RTC → 用户听到回复
                        ↑
                   main_control
                   (主控制器扩展)
```

**main_control 扩展**（位于 `ten_packages/extension/main_python/`）是整个应用的核心控制器，负责：
- 协调各组件之间的消息传递
- 管理对话状态（turn_id, session_id）
- 处理打断逻辑
- 文本校验（TextIntentValidator）

### 1.4 目录结构

```
tenapp/
├── manifest.json              # 应用清单（type: "app"）
├── property.json              # 图结构和扩展配置
├── main.go                    # Go 入口文件
├── bin/main                   # 编译后的可执行文件（Go）
├── go.mod / go.sum            # Go 语言依赖
├── scripts/
│   └── start.sh              # 启动脚本
└── ten_packages/             # 扩展包目录
    ├── extension/
    │   └── main_python/      # 主控制器扩展
    ├── system/
    │   ├── ten_runtime_go/   # TEN Go 运行时绑定
    │   └── ten_runtime/      # TEN 核心运行时（C/C++）
    └── addon/                # Agora RTC 等第三方扩展
```

### 1.5 技术栈详解

| 文件 | 语言 | 说明 |
|------|------|------|
| `bin/main` | Go | 由 `main.go` 编译的可执行文件 |
| `libten_runtime_go.a` | Go | Go 语言绑定（静态链接） |
| `libten_runtime.so` | C/C++ | TEN 核心运行时（动态链接） |
| `libten_utils.so` | C/C++ | TEN 工具库（动态链接） |

### 1.6 运行方式

```bash
# 方式1：使用 tman
cd tenapp
tman run start

# 方式2：直接运行脚本
./scripts/start.sh

# 方式3：通过 API 服务启动（Worker 会启动 tenapp）
curl -X POST http://localhost:8082/start \
  -d '{"channel_name":"test","graph_name":"voice_assistant"}'
```

**voice-assistant** 是一个完整的 AI 语音助手示例项目，位于 `ai_agents/agents/examples/voice-assistant/`。它包含了构建、运行语音助手所需的全部组件。

## 3. API 服务

### 3.1 项目定位

**API 服务** 是 TEN Framework 中 AI Agents 的管理服务，位于 `ai_agents/server/`。它是整个 AI Agent 生态系统的核心控制中心。

### 3.2 核心作用

- **Agent 生命周期管理**：负责启动、停止、监控 AI Agent 实例
- **进程管理**：通过 tman 工具管理 TEN 应用进程
- **RESTful API 服务**：提供 HTTP 接口供前端和其他服务调用
- **资源管理**：管理 Worker 进程的数量、超时和资源释放
- **实时通信**：与 Agora RTC/RTM 集成，处理音视频通话

### 3.3 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                     HTTP Server (Go)                         │
│  端口: 8082                                                   │
├─────────────────────────────────────────────────────────────┤
│                      Worker Manager                          │
│  - Worker Pool 管理                                          │
│  - 超时管理                                                  │
│  - 清理机制                                                  │
└────────────────────────┬────────────────────────────────────┘
                         │ fork/exec
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                      Worker Process                          │
│  运行 TEN 应用（tenapp）                                      │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 核心 API

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | `/health` | 健康检查 |
| GET | `/list` | 获取所有运行中的 Worker |
| POST | `/start` | 启动新的 Agent |
| POST | `/stop` | 停止指定 Agent |
| POST | `/ping` | 心跳保活 |

### 3.5 运行方式

```bash
cd ai_agents/server
go build -o bin/api main.go
./bin/api -tenapp_dir=/path/to/tenapp
```

## 4. Worker 是什么

### 4.1 定义

**Worker** 是由 API 服务启动的一个独立进程，它实际上就是运行中的 **tenapp** 实例。

### 4.2 Worker 进程结构

```
API 服务 (Go 进程，PID 481)
    ↓ fork/exec
sh -c tman run start (PID 7218)
    ↓ fork/exec
tman run start (PID 7220)
    ↓ fork/exec
bin/main --property property-xxx.json (PID 7242) ← 这就是 Worker！
```

### 4.3 Worker 的组成部分

每个 Worker 包含：

| 组件 | 说明 |
|------|------|
| `bin/main` | Go 编译的可执行文件（tenapp 的入口） |
| `property.json` | 独立的配置文件（每个 Worker 一个） |
| 扩展集合 | main_python, agora_rtc, stt, llm, tts, vad 等 |
| 日志文件 | 独立的日志输出 |

### 4.4 Worker 生命周期

#### 创建阶段
```
分配端口 (10000-30000)
    ↓
生成 property.json 配置
    ↓
启动 tman 进程
    ↓
设置进程组
```

#### 运行阶段
```
加载扩展
    ↓
运行图 (Graph)
    ↓
处理消息和数据流
    ↓
定期心跳检查
```

#### 销毁阶段
```
发送 SIGKILL 信号
    ↓
从内存池移除
    ↓
清理日志文件
    ↓
回收端口资源
```

### 4.5 Worker 通信

Worker 与 API 服务之间通过 **property.json 文件** 进行通信（不使用 HTTP）：

```
API 服务
    ↓ 写入 property.json
property.json 文件
    ↓ 每1秒读取
main_python 扩展
```

**优势**：
- Worker 不需要额外的 HTTP 服务器
- 文件系统是共享的
- 更简单、更可靠

## 5. 服务之间的关系

### 5.1 完整关系图

```
┌─────────────────────────────────────────────────────────────┐
│                         用户层                                │
├─────────────────────────────────────────────────────────────┤
│  curl /start, /stop, /ping → API 服务                         │
├─────────────────────────────────────────────────────────────┤
│                       管理层                                  │
├─────────────────────────────────────────────────────────────┤
│  API 服务 (Go)                                               │
│  - 端口: 8082                                               │
│  - 接收 HTTP 请求                                            │
│  - 管理 Workers 生命周期                                      │
│  - 修改 property.json                                        │
├─────────────────────────────────────────────────────────────┤
│                       启动层                                  │
├─────────────────────────────────────────────────────────────┤
│  tman (TEN 包管理器)                                         │
│  - 解析 manifest.json                                        │
│  - 安装依赖                                                   │
│  - 启动 bin/main                                             │
├─────────────────────────────────────────────────────────────┤
│                       运行时层                                 │
├─────────────────────────────────────────────────────────────┤
│  bin/main (Go)                                               │
│  - 加载扩展                                                   │
│  - 启动图                                                     │
│  - 消息路由                                                   │
│                                                               │
│  ┌─────────────────────────────────────┐                    │
│  │  main_python 扩展                    │                    │
│  │  - 处理 ASR 结果                    │                    │
│  │  - 调用 LLM                         │                    │
│  │  - 发送 TTS                         │                    │
│  │  - 读取 property.json 检查 interrupt │                    │
│  └─────────────────────────────────────┘                    │
├─────────────────────────────────────────────────────────────┤
│                       底层库                                  │
├─────────────────────────────────────────────────────────────┤
│  libten_runtime.so (C/C++)  ← 核心运行时                      │
│  libten_utils.so (C/C++)   ← 工具库                          │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 数据流示例

#### 启动流程
```
1. 用户: curl POST /start
   {"channel_name":"test","graph_name":"voice_assistant"}

2. API 服务:
   - 验证参数
   - 生成 property.json
   - 分配端口
   - fork/exec tman

3. tman:
   - 解析 manifest.json
   - 安装依赖
   - 启动 bin/main

4. bin/main (Worker):
   - 加载扩展
   - 运行 voice_assistant 图
   - 开始处理消息
```

#### 打断流程
```
1. 用户: curl POST /interrupt
   {"channel_name":"test"}

2. API 服务:
   - 找到对应 Worker
   - 读取 property.json
   - 添加 interrupt 标记
   - 写回 property.json

3. Worker (main_python):
   - 每1秒读取 property.json
   - 检测到 interrupt 标记
   - 执行打断逻辑
   - 清除标记
```

### 5.3 角色对比表

| 角色 | 对应项目 | 语言 | 数量 | 作用 |
|------|---------|------|------|------|
| API 服务 | `ai_agents/server` | Go | 1 个 | 管理者，接收请求，启动 Workers |
| Worker | `bin/main` | Go | 多个（每个 channel 一个） | 工作者，运行 tenapp 实例 |
| tenapp | `voice-assistant/tenapp` | Go/C/C++ | 1 个（被 Worker 加载） | 应用包，包含扩展和配置 |
| TEN 运行时 | `libten_runtime.so` | C/C++ | 共享库 | 核心引擎 |

### 5.4 关键要点

1. **API 服务是唯一的**：只有一个 API 服务实例在运行，管理所有 Workers
2. **Worker 是按需创建的**：每个 channel 创建一个 Worker
3. **tenapp 是被加载的对象**：它不是独立运行，而是由 Worker 加载
4. **通信通过文件**：API 服务和 Worker 通过 property.json 通信
5. **底层是 C/C++**：Go 程序通过 cgo 调用 C/C++ 核心运行时

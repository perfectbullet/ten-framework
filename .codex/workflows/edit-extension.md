# Workflow: Edit TEN Python Extension

Use this when changing a Python extension under `ai_agents/agents/ten_packages/extension` or the example-local `main_python` extension.

## Standard Files To Inspect

- `manifest.json`
- `property.json`
- `addon.py`
- `extension.py`
- `tests/`

## Editing Pattern

1. Read `manifest.json` to understand registration, dependencies, and API contract.
2. Read `property.json` to understand runtime configuration and env-driven values.
3. Edit Python logic in `extension.py` and related helpers.
4. Only touch `addon.py` if registration or instance creation logic changes.
5. Verify using the extension's standalone tests or the nearest example task.

## Typical Commands

Lint and tests from `ai_agents`:

```bash
task lint
task test-extension EXTENSION=agents/ten_packages/extension/<target_extension>
```

For the local voice-assistant control extension, verify from the example root:

```bash
cd ai_agents/agents/examples/voice-assistant
task run
```

## Watchouts

- Many behavior changes require both code updates and graph/config updates.
- Keep edits in source files only; generated runtime output should be regenerated by tooling.
- This worktree may contain local experimental files. Avoid cleanup that was not explicitly requested.
